# 家計簿 × Jev — レシートの費目判定デモ

LT「Jevで作る実用アプリ：家計簿のデータ設計から動くものになるまで」のデモ。

OCR 済みのレシートテキストを品目ごとに分解し、**Jev の Choice** で費目に分類する。
分類結果は確信度つきで返るので、確信度が低い品目だけユーザーに確認を求められる。

## 動かす

依存パッケージは無い（Node の標準モジュールのみ）。`npm install` は不要。

```sh
export TYPESAFE_API_KEY='sk-...'
node server.mjs
# → http://localhost:3000
```

Node 22 で動作確認済み。

## 構成

| ファイル | 役割 |
| --- | --- |
| `server.mjs` | レシート解析 + Jev 呼び出し。API キーを守るプロキシ |
| `index.html` | 画面。ステージ投影を想定して文字を大きめにしている |
| `TALK.md` | LT の構成案（8分） |

## なぜサーバーを挟むのか

**API キーをブラウザに出さないため。** Jev はクラウド API なので、
クライアントから直接呼ぶとキーが露出する。実アプリでも同じ理由でプロキシが要る。

## 設計のポイント

### 費目は実行時に組み立てる

家計簿の費目はユーザーが追加・編集できるので、固定の enum にできない。
`server.mjs` の `CATEGORIES` を Choice の `criteria` にそのまま渡している。

### 品目が何個あっても API 呼び出しは1回

Jev は `questions` を**並列かつ独立に**評価する。
レシート N 品目に対して question を N 個並べ、1リクエストで投げている。

`state`（レシート全文）は全 question で共通なので、
店名などの文脈がすべての品目の判断に効く。

```json
{
  "state": "スーパーマルエツ 丸の内店\n食パン 198\n歯ブラシ 298 ...",
  "model": "jev-latest",
  "questions": {
    "item_0": { "type": "choice", "instructions": "「食パン 6枚切」は？", "criteria": { ... } },
    "item_1": { "type": "choice", "instructions": "「歯ブラシ」は？",     "criteria": { ... } }
  }
}
```

### 確信度で分岐する

`index.html` の `ASK_THRESHOLD`（既定 0.70）未満の品目は、
費目を確定させずユーザーに確認を求める表示にしている。

汎用 LLM は「分からない」を返さず必ず何か答えてしまうため、この分岐が書けなかった。

## レシート解析について

このデモの解析（`parseItems`）は最小限。金額は**行末の数値**だけを取る。

行全体から数字を消すと `食パン 6枚切` が `食パン枚切` になってしまうため。
住所の行（`東京都千代田区...1-9-1`）も品目として拾わないよう除外している。

実アプリ側は Vision の OCR 結果を扱うので、もう少し複雑な処理をしている。

## Jev についての注意

- **テキスト専用。** 画像・音声・動画は受け付けない（OCR はできない）
- 公式ドキュメント: <https://docs.typesafe.ai>
- `jev-omni` という名前の多モーダルモデルが出回っているが、
  **TypeSafe とは無関係な第三者のモデル**（Gemma のファインチューン）なので混同しないこと
